## 結論

**自動同期候補の生成 → 修正・確認 → 通常／スクロール表示 → 実際の音声付きMP4** の動作試作ができました。画面だけのモックではありません。ただし歌唱精度の完成条件には未到達です。日本語の実歌唱、伴奏付きの利用者の曲、実機Safariは追加検証が必要です。

## 検証素材と同期結果

### 実際の英語歌唱

[Twinkle Twinkle Little Star — sung with full lyrics](https://commons.wikimedia.org/wiki/File:Twinkle_Twinkle_Little_Star_-_sung_with_full_lyrics.ogg)、Dcoetzee / Derrick Coetzee、2012、CC0。125.6819375秒のアカペラです。録音者自身が歌唱の誤りを含むと説明しています。音源をリポジトリに同梱せず、公開元から検証用PCへ取得しました。

- 短い実音源（冒頭27秒・入力4行）で照合を先に実行し、その後UIと接続
- 実際にその位置で歌われていない追加の反復2行を与えた試験では、一致不足として時刻未確定のまま保持
- 曲全体は27行の原文・反復を保持し、27行とも開始＜終了・曲内の自動候補を生成
- 最新ブラウザ経由の同期処理：**73.78秒**。別実行では68〜104秒程度。初回モデル取得時間は含まない
- **24行に、境界差・部分照合・重なり等の追加確認理由あり。そのうち18行に重なり注意**。全27行は、これらの注意がなくても要確認として扱う
- 全文一括照合では一部に数秒のずれがあったため、ASRアンカー周辺の行単位照合へ変更。それでも長音の終了・隣行開始の境界が重なる傾向が残る
- 人手による歌声時刻のアノテーション／聴取採点は未実施。**修正が本当に必要な行数、平均・最大時刻誤差、正確率は未計測**。候補生成数を精度の数字として扱わない

ブラウザ試験で27行を確認済みにしたのは、保存・SRT・MP4までの経路を検査するための自動操作です。人が27行の同期を承認したことを意味しません。試作の出力サンプルも品質保証済みの歌詞動画ではありません。

### 日本語／英語の処理経路

Microsoft Haruka / Ziraによるローカル音声合成、11.825625秒、4行（日本語2行・英語1行・日本語の反復1行）。本文を保持し4区間を推定、41.36秒。照合用テキストと表示原文の分離もユニットテストで確認しました。

これは**実波形を入力した読み上げ音声の試験**です。日本語歌唱や一行内の混在歌唱の精度を実証したものではありません。日本語フォントを使った実MP4の描画／スクロール検査には使いました。

### MV／形式

CC0歌声を使用した12秒の4:3テストMV（FFmpeg testsrc2、640×480、音声開始＋0.5秒）と音声なし版を生成。映像内音声から実際に同期処理を実行し、MVへの字幕合成を確認しました。利用者の完成済みMVはまだ未提供です。

- PC EdgeでWAV・MP3・M4A・H.264＋AACのMP4を選択・再生
- PNG／JPEG背景の選択・表示。PNG背景のスクロールMP4出力
- 音声なしMVへ別音源を選択し、プレビューで動画時刻と音源を同期。元動画はミュート
- MP3／M4Aは短い素材の入力・プレビュー検査。長尺同期・全形式のMV合成を保証する試験ではない
- OGGは検証音源としてPCで抽出・同期済み。SafariでのOGG／WebMプレビューは保証しない
- HEVC、ProRes、DRM、特殊コンテナ／編集リスト、HDR、多音声トラックは未検証

## MP4結果

|出力|時間／仕様|処理時間|
|---|---|---|
|英語歌唱全体・通常字幕|125.682秒、1920×1080、H.264＋AAC、30fps|497.43秒（約8分17秒）|
|4:3 MVへ通常字幕|12.02秒、同じ1080p形式。左右余白で4:3を保持|48.64秒（別再実行では変動）|
|日本語／英語読み上げ・スクロール・PNG背景|11.833秒、同じ1080p形式|57.2秒（別再実行では変動）|

30fpsのフレーム端による長さの差は1フレーム以内。動画はCRF18で再エンコード、音声はAAC指定最大256kbps（元のサンプルレート／チャンネルを保持）。低レート素材では実ビットレートは下がります。

全体歌唱MP4は1秒／62.841秒／120.682秒で元波形と相互相関比較：ラグはいずれも **0.000秒**、RMS比0.998〜0.999。MVと日本語スクロールも3箇所で同様に0.000秒、RMS比約0.999。映像1本・音声1本をffprobeで確認。これは音声の追加ドリフト・二重重ねを検出する検査で、歌詞境界の正確さを測るものではありません。

スクロール出力の1秒／6.7秒／10秒を共通canvas描画と比較。明るい文字画素のIoU **99.66〜99.75%**、RGB平均絶対差約2.96〜2.97/255。YUV／圧縮による色差はあるものの、位置・折り返し・強調・スクロールの一致を確認。出力画像の目視でも通常字幕、日本語字形、スクロール強調、4:3の余白を確認しています。

## 再現手順

READMEの環境を準備し、PCサーバーを起動したまま別ターミナルで実行します。以下は公開CC0テスト素材だけを取得し、利用者の素材を外部へ送信しません。

```powershell
$env:NODE_OPTIONS = '--use-system-ca'
$env:PYTHONUTF8 = '1'
node engine/prepare-fixtures.mjs
.venv/Scripts/python.exe engine/verify_alignment.py --full
node engine/browser-test.mjs
```

日本語の読み上げ試験はWindowsの該当音声が必要です。声がない環境では実施せず、日本語歌唱を代わりに検証したことにもなりません。

```powershell
& ./engine/japanese-speech-fixture.ps1
.venv/Scripts/python.exe engine/japanese-probe.py
node engine/integration-test.mjs
node engine/mobile-test.mjs
node engine/verify-render.mjs
```

証拠ファイルは `.studio-data/verification/`、最終動画・JSON・画素検査・ブラウザ結果はその中の `browser/`。モデル・音源・生成動画は大容量／利用者データ保護のためGitへ含めません。

## 未完了／既知の制限

- 利用者の完成MV、日本語・混在歌唱、伴奏の強い曲、ラップ、重唱、長い前奏・間奏を含む一曲の聴取採点が必要
- 前奏／間奏で字幕を消す描画・未一致行を未配置にする処理は実装済み。ただし音声認識が伴奏を誤認する問題は残り、強い伴奏で無音端を見つけられない
- 同じ歌詞が一部だけ省略された曲では単調文字照合が別の反復へ寄る可能性あり。重唱は単一表示レーンで、重なり中は最初の区間を優先する。要確認理由から手動で整理する必要あり
- 長音の開始／終了候補に重なりあり。歌唱精度の自動保証・自動確認済みへの昇格は行わない
- 最大5分／1GB。CPU書き出しは実時間より遅い。長曲・高性能GPU・低メモリPCは未確認
- iPhone／iPad実機での選択・再生・ピンチ・Safariのダブルタップ・LAN接続・MP4ダウンロードは未確認。Chromiumの画面幅検査で代用済みとはしない
- 接続PCへのコピーが必要。GitHub Pages単独、外出先からのアクセス、iPhoneだけの推論・書き出しはできない
- LAN接続はHTTP、信頼できる家庭内ネットワーク専用。本番サーバーではない
- 素材／ログの自動消去、サーバー再起動後のジョブ・素材復元、画面を閉じた後の進捗再接続は未実装
- Windowsでブラウザ接続を閉じた際、開発サーバーの終了ログにConnectionResetErrorが出ることあり。今回の完成ジョブ／再起動／ヘルス確認は成功
- 別音源がMVより短い／長い場合、先頭を合わせて音声をパディング／終端切り詰め。任意の別音源オフセット編集は未実装
- 透過動画、単語／一文字の色塗り、歌声分離、映像生成は対象外
- ソフト本体の販売ライセンス／配布パッケージは未設定。モデル・フォント・FFmpeg等の通知と配布条件の整理が必要
