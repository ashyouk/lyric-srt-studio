# Lyric SRT Studio

公開中の **v2.3.3 β版（ルート画面）** は、曲を再生しながら歌詞行の開始・終了時刻を記録し、日本語・English・日英併記の SRT 字幕を作成するローカルファーストのブラウザアプリです。この手動版では音源・歌詞・プロジェクトデータは外部へアップロードされません。

## 新開発：歌詞入り動画の動作試作

### PC不要の自動同期：端末内解析 実験0.4.0

`video/auto.html` は別入口の技術検証版です。通常の `video/editor.html` と公開手動β版を置き換えません。Web Worker内で多言語Whisper tinyの量子化モデルをWASM・単一スレッドで実行し、実音響の単語時刻を入力歌詞へ連続一致のアンカーで対応させます。本文を認識結果で上書きせず、対応不足の行は未配置、すべての候補を要確認にします。曲長による均等分割やダミー結果ではありません。

音源→歌詞→モデル取得の注意事項に同意→「自動同期」→聴いて修正・確認→作業JSON／SRT保存。まず冒頭30秒で試し、必要なら曲全体へ。音源のみ、5分・100MB以内です。MVの音声抽出・MP4生成はこの画面にはありません。ブラウザがデコードできるWAV／MP3／M4Aを対象とし、今回の実再生・解析検証はWAVです。

**重要：PCブラウザで解析処理は動きましたが、日本語の伴奏付き実曲の精度は実用に達していません。** 27秒の英語アカペラでは4行の候補ができた一方、提供された日本語実曲114.48秒29行では軽量モデルの対応が不足しました。iPhone／iPad実機の動作・速度は未確認です。販売可能・全曲自動完成とは扱いません。[検証と制限](docs/BROWSER-EDITOR-VERIFICATION.md)

音源・歌詞は端末内だけで処理します。月額契約・音声API・PC接続は使いません。実行時のみHugging Faceから固定リビジョンのモデル約45MBをGETで取得します（ページ側の処理プログラム約23MBも初回取得）。Wi-Fiと空き容量が必要です。モデルはブラウザキャッシュに保存できる場合がありますが、端末の判断で消えることがあります。画面を閉じる／端末をロックすると処理が中断する可能性があります。

`npm.cmd run test:browser-sync` はモデル取得を伴う任意の実処理テストです。通常の `npm.cmd test` にモデル取得はありません。[同梱ランタイム・モデルのライセンスと商用配布時の未確認事項](video/vendor/transformers-3.8.1/NOTICE.md)

### PC接続不要：端末内SRT編集 β 0.3.1

`video/editor.html`（または `video/index.html?mode=browser`）は、音源の再生・タイミング修正・プロジェクト保存・SRT出力を端末内だけで行う編集画面です。静的ホスティングで利用でき、**Pythonサーバー、PCへの接続、音源アップロードは不要**です。GitHub Pages上の `video/` は自動的にこのモードになります。既存ルートのv2.3.3手動版と、ローカル `video/` のPC処理版は維持します。

公開試験URL：**https://ashyouk.github.io/lyric-srt-studio/video/editor.html** 。既存の手動β版は従来のルートURLです。公開側へ追加したのは `video/` の静的ファイルだけで、PCの処理サーバーは公開していません。[検証結果・未確認項目](docs/BROWSER-EDITOR-VERIFICATION.md)

スマホ向けに主要操作を同梱SVGアイコン＋短い名前へ整理しました。補足説明は初期状態で非表示です。上部の「ガイド ON/OFF」で切り替え、詳しい手順は「？ 使い方」で確認できます。ガイド設定は端末に保存します。エラー・品質警告・選択行・確認状態・保存結果はガイドOFFでも表示します。書体サンプルは折りたたみ表示です。データ形式と編集履歴の仕組みは変更していません。

1. PC版で自動同期後、「プロジェクトを保存」でJSONを保存します。
2. JSONと同じ音源をスマホ／タブレットへ移し、端末内編集画面でJSONを開きます。
3. 音源を選び直します。素材はBlob URLで再生され、外部送信されません。ファイル選択のaccept制限は付けません。
4. 「タイミング修正」で再生し、行全体の±0.1秒／開始・終了の指定／Undo・Redoを使って修正します。聴いて確認した行を「確認済みにする」で承認します。
5. 作業用JSONとSRTを保存します。SRTに含むのは、有効な開始・終了を持つ確認済み行だけです。未配置・要確認行は含めません。

- **この画面で自動同期・MP4作成はできません。** それらは従来どおりPC版で行います。クラウドや外部APIへ接続しません。ページ・同梱フォントの読み込みには接続が必要です（完全オフライン配布／PWAは未実装）。
- PC版とのJSON形式は同じversion 1です。本文・空行・繰り返し・照合用テキスト・自動推定／手動修正時刻・要確認状態・書体を保持します。素材本体と一時再生URLはJSONに含めません。再読込時は再選択が必要です。
- PC処理版とはブラウザ自動保存のキーを分けています。ブラウザを閉じる前にJSONも保存し、別端末へはファイルで移してください。新しいプロジェクトを開く際は、既存作業を置き換える確認を出します。
- 想定形式：MP3・M4A・WAV、H.264のMP4、背景PNG・JPEG。実際の再生可否はブラウザのデコーダーに依存します。動画の音声有無は端末内版では自動判定せず、必要なら追加音源を指定します。
- SRT自体には書体・色・位置情報は入りません。見た目の設定はプレビューとプロジェクトJSONに保存します。
- iPhone／iPad実機Safariのファイル選択・長時間再生・保存動作は未確認です。ブラウザ幅を変える自動テストとは区別してください。
- ローカル確認URL：`http://127.0.0.1:8765/video/editor.html`。これはPC上の確認用です。スマホでPC接続なしに試す場合は、別途静的ページを公開したURLを使用します。

検証：`npm.cmd test`（既存テスト＋端末内素材管理）、`npm.cmd run test:browser-editor`（Python/APIなしの静的サーバーで、実WAV再生・修正・保存・SRT・画面幅・別窓を確認）。ブラウザテストの音源は `.studio-data/verification/twinkle-short.wav`、または `STUDIO_EDIT_AUDIO` で指定します。テスト用時刻はUI動作検証専用で、自動同期結果や精度評価としては扱いません。

`STUDIO_BROWSER_EDITOR_URL` を上記サイトのルートURLへ設定すると公開静的ページを検証します。この場合、API宛て・GET/HEAD以外・他オリジンへのHTTP通信は検証ブラウザで遮断し、素材が意図せず送信されないようにします。

`agent/lyric-video-prototype` ブランチの `video/` と `engine/` に、別画面の試作を追加しています。公開β版のHTML・CSS・JavaScriptは変更していません。販売完成版ではなく、実音源で同期・修正・音声付きMP4出力を検証する段階です。

- 音源／既存MVと入力歌詞を、PC上のWhisper＋Qwen3強制アラインメントで行単位に照合
- 本文と照合用テキストを分離。認識結果で歌詞を置き換えず、空行・構成タグ・繰り返しも保存
- 通常字幕／スクロール歌詞、文字サイズ・色・影・位置・幅の調整
- 要確認行への移動、開始／終了の±0.1秒修正・現在位置記録、複数段階Undo／Redo
- 手動修正した行を再同期で上書きしない。要確認の候補も含む試写MP4と、確認済みMP4を区別。確認済みMP4とSRTは同じ確定時刻を使用
- 元MVを切り取り・引き伸ばしせず、16:9へ余白を付けて合成。元音声は一度だけ使用
- 音声がないMVへの別音源、音源＋任意のPNG／JPEG背景、素材参照付きJSON保存
- 旧SRTプロジェクトは別形式へ取り込み、元のデータも保存。旧ファイルを上書きしない

### 試作0.2：プレビューしながら修正

- **制作／タイミング修正**のアプリ内タブ。切り替えても素材・歌詞の下書き・再生位置・解析結果・Undo／Redoを保持します
- 修正タブの「すべて／要確認」で表示を絞れます。選択行と再生中の歌詞行は別表示です
- 行番号で開始の0.5秒手前へ移動。「この行を聴く」で試聴し、「0.1秒早める／遅らせる」で開始と終了を一緒に移動。表示時間を保ち、曲外への移動を拒否します。開始だけ・終了だけの修正と現在位置の記録も使えます。調整で再解析や再シークはしません
- 歌詞フォントは **Noto Sans JP／Noto Serif JP／Zen Maru Gothic**。実書体のサンプルから選択でき、プレビュー／MP4／プロジェクト保存へ反映。旧プロジェクトは従来のNoto Sans JP。全候補が日本語・英語対応、フォント読込完了後に改行・行高を再計算します。[同梱ファイル・OFLライセンス](video/fonts/README.md)
- 「別窓で開く」で映像と歌詞だけを切り離せます。繰り返し押すと同じ窓へフォーカスし、閉じる／「画面内に戻す」で復帰。ブラウザがポップアップを制限する場合は、許可するか埋め込み表示を使ってください
- 別窓は同一オリジンの親画面へ直接接続し、親の素材と現在時刻を共通描画で映します。**子窓に音源・動画プレーヤーや別の再生時計はありません**。修正、停止中の変更、Undo／Redo、フォントも再読込せず反映します。親画面を閉じると別窓も閉じます
- iPhone／iPad向けには修正タブに追従するコンパクトプレビューを配置。行の入力欄へフォーカス中は追従を解除し、コンパクト映像を畳んでキーボードの場所を確保します。実機Safariの窓管理・キーボード挙動は未確認です

すでに開いている試作を更新する場合、先にプロジェクトを保存してからブラウザを再読込してください。素材本体は保存JSONに含まれないため、再選択が必要です。新しいタブへ素材を送信する操作ではなく、起動したPC内の既存素材を表示します。

### 処理場所と費用

**新試作の素材は、起動した処理用PCへコピーされます。** iPhone／iPadから同じLANで操作する場合は、その端末からPCへ素材が送られます。外部音声API、クラウド保存、課金サービスは使用しません。初回だけ公開モデルをダウンロードします（素材はモデル配布元へ送りません）。モデル利用の従量料金は0円ですが、PC・通信・電力が必要です。

GitHub Pagesだけで動くのは既存の手動版です。新しい自動同期・MP4書き出しには下記のPCプログラムが必要で、Pagesへブランチを置いただけでは動きません。

### 起動（検証環境：Windows 10、Python 3.13、Node.js 22、RAM 16GB）

FFmpeg／ffprobe（libx264・AAC対応）とEdgeまたはChromeを用意し、リポジトリのフォルダーでPowerShellから実行します。専用GPUは不要です。初回のモデル・依存関係取得には数GB、作業用ディスクには10GB以上の余裕を推奨します。

```powershell
py -3.13 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
$env:NODE_OPTIONS = '--use-system-ca'
npm.cmd ci
```

```powershell
$env:PYTHONUTF8 = '1'
.venv/Scripts/python.exe engine/server.py
```

PCのブラウザで **http://127.0.0.1:8765/video/** を開きます。素材・歌詞を入力して「歌詞を自動で合わせる」→プレビュー→「歌詞入りMP4を作る」→「試写MP4を保存」。初期設定の試写は要確認の有効な候補も含め、確認状態を変えません。聴いて修正・確認後は、出力範囲を「確認済みの歌詞行だけ」に切り替えて書き出してください。SRTは従来どおり確認済み行だけです。終了は起動したターミナルでCtrl+Cです。Edge／Chromeが見つからない環境では `npx.cmd playwright install chromium` が別途必要です。

スマホから試す場合は、PCと同じ信頼できる家庭内LANで次の起動に切り替えます。

```powershell
.venv/Scripts/python.exe engine/server.py --lan
```

起動時に表示される接続URLの `<this-PC-IP>` をPCのLAN内IPv4アドレスへ置き換えて、iPhone／iPadから開きます。起動ごとのアクセス文字列は公開しないでください。必要ならWindowsのファイアウォールで**プライベートネットワークだけ**を許可します。HTTP接続のため、公衆Wi-Fi・インターネット公開・ポート転送では使わないでください。実機Safariでの操作とPCへの接続はまだ未確認です。

### 初版の範囲

- 5分以内・素材1GB以内。同期対象1000行／3万文字以内
- 基本検証：WAV、H.264＋AACのMP4。その他の形式の確認状況は[検証報告](docs/VIDEO-VERIFICATION.md)に記載
- 出力：MP4／H.264 CRF18／AAC最大256kbps／1920×1080／30fps。素材の順序・速度・長さを維持し、異なる縦横比は余白で処理
- すべての自動推定を「要確認」にします。未歌唱・一致不足の行には架空の時刻を埋めません。精度保証や全楽曲対応の表示はしません
- 同期設定から認識モデルを選択可能。画面の初期選択は`large-v3-turbo`（歌声の認識を重視、初回モデル約1.62GB）、メモリを抑える選択肢は`small`。大きいモデルも歌唱・境界の精度を保証しません。CLIでモデル未指定時は従来どおり`small`、`LYRIC_ASR_MODEL`またはリクエストの`asrModel`で選択できます
- 初回モデル取得とCPU処理には時間がかかります。処理段階・キャンセル・再実行に対応。画面を閉じるとPC処理は続きますが、再接続での進捗復元は未実装
- 素材は `.studio-data/media/`、変換音声・結果・ログは `.studio-data/jobs/` に残ります。自動消去・暗号化は未実装。終了後に不要な素材を自分で整理してください。これらはGitに含めません
- 保存JSONに素材本体を含めません。再読込やサーバー再起動後は素材を再選択してください
- 日本語／混在歌唱、ラップ、重唱、強い伴奏、長い間奏での精度は未保証。利用者の実曲・正しい歌詞が必要です

利用者から提供された検証曲・歌詞・同期候補・試写動画は、`.studio-data/user-check/`へ保存し、リポジトリや公開PRへ含めません。試写用の候補出力と、利用者が聴いて承認した完成出力は区別します。

方式選定・商用利用上の注意は[技術選定とライセンス](docs/AUTO-SYNC-DESIGN.md)、実施済み／未確認項目は[検証報告](docs/VIDEO-VERIFICATION.md)を参照してください。

以下は従来の手動SRT版についての説明です。

## 主な機能

- 歌詞をまとめて貼り付け、行単位の字幕へ変換
- 日英歌詞の内部空行を位置情報として保ち、行対応のずれを防止
- ファイル選択またはドラッグ＆ドロップで音源を読み込み
- Space キーまたは画面固定ボタンで開始時刻を連続記録
- J / K / L キーで3秒戻る・再生/停止・3秒進む、E キーで終了時刻を記録
- 次の字幕直前まで終了時刻を自動設定
- 必要な行だけ終了時刻を手動指定
- ±0.1秒 / ±0.5秒の微調整、最大100件の Undo / Redo
- スマートフォン・タブレットでは作業中の Undo / Redo を固定編集コンソールから操作可能
- 端末内での波形解析と字幕プレビュー
- 波形と同じ時間軸で確認できる字幕タイムライン
- 曲全体を収める全体表示と、横スクロールできる編集表示
- 歌詞行追従をONにすると、開始記録後に次の未記録行を見やすい位置へ表示（編集表示ではタイムライン内部も追従）
- 記録漏れ、時刻逆転、長すぎる表示、言語抜けなどの品質チェック
- 日本語・English・日英併記 SRT の書き出し
- UTF-8 BOM の有無を選択可能
- ブラウザへの自動保存
- JSON プロジェクトファイルの保存・読み込み
- 歌詞を残したまま全時刻を一括消去（直後の取り消しに対応）
- 旧バージョンのブラウザ保存データからの移行

## 使い方

1. 「曲を選ぶ」またはドラッグ＆ドロップで端末内の音源を読み込みます。
2. 日本語歌詞と、必要なら英語歌詞を1行ずつ貼り付けて「歌詞一覧に反映」を押します。
3. 曲を再生し、歌い始めに合わせて「開始を記録」または Space キーを押します。記録した歌詞は波形下の字幕タイムラインへ即時表示されます。
4. 長い間奏などで字幕を先に消したい場合は、その行の「終了を記録」を使用します。
5. プレビューと完成度チェックを確認し、必要な言語の SRT を書き出します。
6. 作業を別の端末やブラウザへ移す場合は「プロジェクトを保存」を使用します。音源そのものはプロジェクトに含まれないため、読み込み後に選び直してください。
